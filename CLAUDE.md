# CLAUDE.md

Guidance for Claude Code when working in this repo.

## What this is

Online XSD/XML Viewer — FastAPI backend + React SPA, deployed as a single
Docker container. Upload an XSD, get a tree/diagram/text view.

For a deep dive on how the pieces fit together, read
**[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** first.

## Repo layout (cheatsheet)

- `backend/app/` — FastAPI app; parser lives in `app/parser/xsd_parser.py`,
  Pydantic models in `app/parser/model.py`.
- `frontend/src/` — React + Vite SPA; Zustand store in
  `stores/selectionStore.ts` is the single source of truth for views.
- `backend/app/spa.py` — SPA shell with per-route meta (`ROUTE_META`, mirrored in
  `frontend/src/lib/modeRoute.ts`), `/sitemap.xml` (generated), `/<INDEXNOW_KEY>.txt`, the home
  FAQ (`<!--faq-->` markers in `index.html`), og tags naming the schema of a shared `/url?src=`
  link, and `/embed` — the diagram alone for iframes (`components/EmbedView.tsx`), the only route
  with `frame-ancestors *` and no `X-Frame-Options`, `noindex`, page views with `source=embed`.
- `backend/app/content/` — server-rendered Markdown pages without JS (SEO): `pages/**/*.md` with
  TOML front matter between `+++`, `faq.toml`, `site.py` (per-site constants and the FreeXmlToolkit
  family list); the rest is shared with the XML and OData viewers — keep it in step.
  `pages/fundsxml/<tag>.md` + `releases.md` are generated by `tools/build_fundsxml_pages.py`
  (parses every release, `app/parser/schema_diff.py` compares it with the previous one); rerun
  and commit after a FundsXML release. It also draws each release's preview image
  `frontend/public/og/fundsxml/<tag>.png` (`tools/fundsxml_og_image.py`, Pillow from the dev
  extra, fonts in `tools/fonts/`), named by `og_image` in the front matter; pages without it use
  `og-image.png`.
- **ISO 20022 tab** (`/iso20022`, `?message=pain.001.001.12` loads directly, `?q=` prefills the
  search): `backend/app/api/iso20022.py` serves `app/standards/iso20022_catalog.json` (written by
  `tools/build_iso20022_catalog.py`) and loads a message by id from the public mirror
  `phoughton/pyiso20022`, pinned to one commit — iso20022.org refuses automated downloads. The URL
  is built from the catalogue only. Source kind `iso20022` in `lib/schemaSource.ts`, tab component
  `components/Iso20022Messages.tsx`, usage `source=iso20022`.
- **Content links.** `/guides` is generated from all pages per `site.HUB_SECTIONS`; a test
  fails on any page it cannot reach. The SPA landing links the main pages and `/guides`;
  `GET /api/content/pages` lists the slugs that exist.
- `e2e/tests/` — Playwright golden-path test.
- `Dockerfile`, `docker-compose.yml` — container build and local sandbox.

## Running locally

```bash
# Backend
cd backend && pip install -e ".[dev]" && uvicorn app.main:app --reload

# Frontend (separate terminal)
cd frontend && npm ci && npm run dev
# Vite dev-server proxies /api to the backend.
```

## Tests

- Backend: `cd backend && pytest` (also `ruff check`). `xmlschema` is a runtime
  dependency, but the app never imports it: XSD 1.1 validation runs it in a
  worker process (`app/parser/xsd11_worker.py`, started by `validation.py`).
  Tests and `tools/sample_audit.py` also use it directly as a second validator
  for generated samples (XSD 1.1, IDREF targets — neither of which libxml2
  checks).
- Frontend: `cd frontend && npm run test` (Vitest) and `npm run build` for
  the TS typecheck via `tsc --noEmit`.
- E2E: `cd e2e && npm ci && npx playwright test` — boots the backend with
  `STATIC_DIR=../frontend/dist`, so run `npm run build` in `frontend/` first.
  Three projects: `chromium` (desktop, all specs) plus `phone` and `tablet`
  (Chromium with iPhone/iPad emulation, only `tests/mobile.spec.ts`). If port
  8080 is taken on your machine, set `E2E_PORT=8090`.

- Conformance: `tools/w3c_suite.py` runs the W3C XML Schema test suite
  (`--fetch` clones it into `~/.cache/xsd-viewer/xsdtests`; it is not in this
  repo) through the upload, validation and sample-generator code and lists
  where the app disagrees with the expected results. A full run takes a while;
  `--only <test set>` narrows it, `--compare before after` shows regressions.
  Most invalid samples left are ones the generator reports as beyond it (a
  strict wildcard nothing is declared for, a key on a node without a simple
  value); the summary's "invalid samples the generator did not report" is the
  list of actual defects.

## Deployment (read before redeploying)

- **Local sandbox** — `docker compose up -d --build` builds
  `online-xsd-viewer:latest` and runs a container on `127.0.0.1:8091`.
  For local testing only; **not** what the public site serves.
- **Public site** — **https://www.xsd-viewer.online/**, served by Google
  Cloud Run service `xsdviewer` in project `xsd-viewer-495407`, region
  `europe-west1`. The apex `xsd-viewer.online` is mapped too; `main.py` redirects it to
  `SITE_ORIGIN` (301 for GET/HEAD, 308 otherwise). Redeploy from the repo root — Cloud Build rebuilds
  from the `Dockerfile`, creates a new revision, and shifts 100 % traffic;
  existing service config (env vars, memory, scaling) is retained.

  Always pass `--project xsd-viewer-495407` explicitly: your active gcloud
  config may default to a different project, in which case omitting the flag
  deploys to the wrong project and silently creates an unrelated `xsdviewer`
  service there instead of updating the public site.

  ```bash
  scripts/deploy.sh   # downloads GeoLite2 DB into backend/geoip/, then:
  # gcloud run deploy xsdviewer --source . --region europe-west1 --project xsd-viewer-495407
  ```

  Prefer the script: without the `.mmdb` in `backend/geoip/` the image falls
  back to a per-instance MaxMind download, which hits their daily limit
  (HTTP 429) and leaves `country_code` NULL in the usage stats.

  Full setup, sizing, env-var and rollback details:
  `docs/DEPLOY_GCLOUD.md`.

After deploying, hard-reload the browser (Ctrl+F5) — the SPA JS bundle is
cached and a soft reload can keep showing the old UI.

## Conventions worth knowing

- **Sister sites and usage stats**: links to the XML/OData viewers and the Fund Data Converter (formerly TPT converter) go through
  `/go/xml-viewer`, `/go/odata-viewer`, `/go/tpt-converter` (`app/api/go.py`), which add `utm_source=xsd-viewer` — the sites send no
  Referer. Page views store `utm_source`/`utm_medium`/`utm_campaign` (slugs only), the Share button
  pings `POST /api/usage/share` (event `share`). New `usage_event` columns must exist in the DB
  (`backend/sql/usage_stats.sql`) **before** deploying: the insert names every column.
- **Error messages**: `api/client.ts` `errorFromResponse` turns a 403/407 without our JSON body
  into "blocked by a proxy/firewall" — the app itself never answers 403 (GitHub issue #1).

- **ID scheme**: all declarations are `"{kind}:{qname-or-path}"` — see the
  ID-scheme section in `docs/ARCHITECTURE.md`. The same id flows through the
  API, Zustand index, URL hash, and React Flow node ids.
- **Model contract**: `SchemaModel` is mirrored by hand between
  `backend/app/parser/model.py` and `frontend/src/types/schema.ts`. Keep them
  in sync when changing shapes — this now also covers `IdentityConstraint`
  (`ElementDecl.identity_constraints`), `IdRole` (`ElementDecl.id_role` /
  `AttributeDecl.id_role`), `ComplexType.simple_content_inline`,
  `any_attribute` (`ComplexType` / `AttributeGroup`), `SchemaModel.redefines`,
  `block` / `final`, `ElementDecl.substitution_groups`, the `wildcard_not_*`
  particle fields, the schema-level `annotation`, `schema_version` and
  `notations`, `ComplexType.default_attributes`, `OpenContent.origin`,
  `OverrideReplacement.original_source_ref`, the `Annotation` extras (`xml_id`,
  foreign `attributes`, `context` / `source_uri` on its entries),
  `IdentityConstraint.field_xpath_default_namespaces` and `ref` / `ref_id`
  (a constraint used by reference), the effective
  `qualified` on local `ElementDecl` / `AttributeDecl` and the per-file
  `element_form_default` / `attribute_form_default` on `SourceFile`. Outside
  the model, `SchemaCheckResponse` (`validation.py`, the schema check) is
  mirrored the same way.
- **Not every tree row is a declaration**: `xs:any` / `xs:anyAttribute` rows
  carry a synthetic id and select their owner; `xs:notation` is a real node
  kind (`notation:…`). The attribute wildcard shown is the one in effect
  (`lib/wildcards.ts`), not just the type's own.
- **XSD semantics are applied, not just shown**: `xs:redefine`, `xs:override`,
  `vc:*` conditional inclusion (as an XSD 1.1 processor) and the per-file
  `defaultAttributes` / `xs:defaultOpenContent`. The model holds the effective
  schema; what was replaced or excluded is only in the source text.
- **Parser choice**: we parse with lxml, not `xmlschema`, because we need to
  preserve annotations, appinfo, comments, and source line numbers. Validation
  is libxml2 for XSD 1.0 and `xmlschema` (worker process) for XSD 1.1.
- **Default tab is `diagram`** (`selectionStore.ts`), enforced by the e2e
  golden-path test.
